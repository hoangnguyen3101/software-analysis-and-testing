# Software Analysis and Testing

Coursework for the *Software Analysis and Testing* module — Phenikaa University, Semester I, 2026–2027.

Each lab is a self-contained folder: a small Java program under test, a JUnit 5 test suite, and a write-up in `docs/` that explains how the test cases were derived. The write-ups are in Vietnamese; the code and test names are in English.

## Labs

| Lab | Topic | Technique | Program under test | Tests |
| --- | --- | --- | --- | :-: |
| [Lab01](Lab01/) | Tiered electricity billing | Statement coverage, path coverage | `ElectricityBill.calculateBill` | 4 |
| [Lab02](Lab02/) | Train ticket pricing by departure time | Equivalence partitioning, boundary value analysis | `TrainTicket.getTicketType` | 22 |
| [Lab03](Lab03/) | Triangle classification | Control flow graph, cyclomatic complexity, basis paths, statement & branch coverage | `Triangle.classify` | 5 |
| [Lab04](Lab04/) | Web performance and accessibility audit | Lighthouse audits of 2 sites (14 reports) | — | — |
| [Lab05](Lab05/) | Promotions, insurance premiums, exam eligibility, shipping fees | Decision table testing | 4 modules | 44 |

### What each lab produces

- **Lab01** — white-box coverage on a loop with a tiered tariff. Tests are split into a statement-coverage set and a path-coverage set.
- **Lab02** — black-box design. Seven equivalence classes and the boundaries around 09:30, 16:00, 19:30 and midnight, including invalid input handling. See [the analysis](Lab02/docs/Bai02-Vung-tuong-duong-va-gia-tri-bien.md).
- **Lab03** — a CFG with 10 nodes and 13 edges, cyclomatic complexity of 5 computed three ways, five basis paths, and a 5-case suite reaching 100% statement and branch coverage. Coverage is measured with JaCoCo. Figures under [`Lab03/docs/images/`](Lab03/docs/images/) are generated by [`Lab03/tools/figures.py`](Lab03/tools/figures.py), and [`build_docx.py`](Lab03/tools/build_docx.py) builds the accompanying study guide.
- **Lab04** — Lighthouse reports (performance, accessibility, best practices, SEO) saved as HTML, plus a written report.
- **Lab05** — conditions, actions, a decision table and the resulting test cases for four specifications, including rule priority and boundary values for the shipping policy.

## Requirements

- JDK 17 or newer
- Maven 3.9 or newer
- Python 3.10+ with `matplotlib` and `python-docx`, only if you want to regenerate the Lab03 figures

## Running the tests

Every lab has its own `pom.xml`, so run Maven from inside the lab folder:

```bash
cd Lab05
mvn test
```

Lab03 also writes a JaCoCo coverage report:

```bash
cd Lab03
mvn test
# open target/site/jacoco/index.html
```

## Layout

```
.
├── Lab01/  Lab02/  Lab03/  Lab05/     Maven projects
│   ├── pom.xml
│   ├── README.md                      lab overview and how to run it
│   ├── docs/                          test design write-up
│   └── src/
│       ├── main/java/                 program under test
│       └── test/java/                 JUnit 5 test suite
└── Lab04/                             Lighthouse reports and the written report
```

Build output (`target/`) is ignored by git.

## Workflow

Each lab is developed on its own branch (`lab02`, `lab3`, `lab05`, …) and merged into `main` through a pull request, so the history shows one reviewable change per lab.
